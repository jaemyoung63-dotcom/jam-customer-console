# 홈 화면 6탭 구조 설계 — 논의 정리 (2026-09-06)

> **진행 상황 (2026-09-06)**: 1단계(탭 6개 재배치 + 홈 아이콘 이동) 구현 완료. TA·고객관리는 아직 "준비중" 빈 화면만 연결된 상태 — 2·3·4단계는 미착수.

## 1. 왜 바꾸려는가
지금은 홈+고객/참조풀/분석/상담(AP), 5개 하단 탭 구조. 그런데 실제 영업 흐름(전화 → 정보 입력 → 자료 매칭 → 분석 → 상담 준비 → 실제 만남 → 사후 관리)이 화면 순서에 그대로 안 드러나 있음. 화면 순서를 실제 업무 순서와 맞추고, 지금 앱에 아예 없는 "상담 이후 히스토리 관리"를 새로 추가하려는 것.

## 2. 전체 구조

**하단 탭 6개**, 왼쪽부터 순서대로:

```
TA → 고객정보 → 참조풀 → 분석 → 상담(AP) → 고객관리
```

- **홈**은 하단 탭에서 뺀다. 대신 **모든 화면 상단 우측에 홈 아이콘**을 고정으로 둔다.
- 참조풀/분석/상담(AP)은 지금 화면 그대로 — 이름·기능 변경 없음, 순서만 이동.
- 고객정보 = 지금 "고객" 탭과 동일 (이름만 확정 필요, 아마 그대로 두거나 "고객정보"로 라벨 변경).

## 3. 각 탭이 하는 일 (실제 업무 흐름 기준)

1. **TA** — DB 고객·지인 고객에게 전화하거나 상담할 때 쓸 "전화 요령·상담 요령" 자료를 보여주는 화면. (아이스브레이크 참조풀과는 **완전히 별개** — 혼동 금지.)
2. **고객정보** — 전화/상담으로 정보동의를 받은 뒤, 고객 정보 입력 + 보장급부·내보장자산·기타 자료 등록 + AI로 정리.
3. **참조풀** — 이 고객의 니즈에 맞는 자료를 참조/선택.
4. **분석** — 고객정보 + 참조풀 자료를 매칭해서 보장분석 → 가입설계 → 재분석까지 진행.
5. **상담(AP)** — 실제 고객을 만나기 직전, 상담 준비를 최종 점검하는 화면. (지금 AP 화면과 동일)
6. **고객관리** (신규) — 여기가 이번 개편의 핵심. 아래 4번 항목에서 자세히.

> 참고: 실제 고객을 만나서 상담하는 행위 자체는 앱 화면이 아니라 오프라인에서 일어남. 상담(AP)까지가 "준비", 고객관리가 "그 이후 기록".

## 4. 고객관리 탭 — 상세 설계

### 목적
TA부터 고객을 만나기까지의 통화 내역, AP 상담 내용(녹취) 등 **이 고객과 있었던 모든 히스토리**를 한 곳에 모아서, 나중에 쉽게 찾아볼 수 있게 한다.

### 입력 방식 (jam님 확정)
- 음원 파일을 **드래그&드롭 / 폴더에서 선택 / 구글 드라이브에서 가져오기**, 세 가지 방식으로 넣는다.
- **"AI로 정리" 버튼**을 누르면:
  1. 음원 → 텍스트 변환 (참조풀에서 쓰는 Whisper 방식과 같은 구조 재사용 가능)
  2. 변환된 텍스트를 AI가 "언제, 무엇을, 어떤 내용으로 했는지" 형태의 히스토리 기록으로 정리
  3. 이 고객의 히스토리 타임라인에 쌓임

### Q&A 코너
- 고객관리 안에 **별도 창(팝업)**으로 Q&A 코너를 만든다.
- 사용자가 자유 질문을 입력하면, 그 고객의 저장된 히스토리를 근거로 AI가 답변.
- 예시 질문(jam님 제시):
  - "내가 언제쯤 이 고객과 통화했는데 반응이 어땠어?"
  - "언제 내가 이 고객을 다시 만나면 좋겠어?"
  - "이 고객을 만날 때 어떤 내용을 가지고 접촉하면 좋겠어?"

### 기존 기능과 연결
- 상담(AP) 화면의 "상담결과 입력"(성공/보류/실패 + 다음일정 + 메모, `ap.js openConsultResult`)도 고객관리 히스토리에 자동으로 얹혀야 함.

## 5. 아직 결정 안 된 것 / 확인 필요 (제가 드린 의견 포함)

- **구글 드라이브 연동** — 지금 앱엔 없는 기능이라 새로 붙여야 함(로그인 연동 필요). 별도 작업량으로 잡아야 함.
- **통화 내역은 자동 기록이 안 됨** — 앱이 전화 거는 기능 자체가 없어서, "언제 통화했는지"는 결국 jam님이 음원을 넣거나 짧게 메모를 남겨야 쌓이는 구조. "자동으로 다 기록된다"는 기대는 하지 않는 게 맞음.
- **Q&A 비용** — 고객별 히스토리가 쌓일수록 매번 AI에 보내는 글자 수(=비용)가 늘어남. 참조풀에서 쓰는 것처럼 "미리 압축된 요약"을 같이 저장해두는 방식이 필요할 가능성 높음. 정확한 비용은 지금 추측하지 않고, 실제로 만들 때 계산해서 알려드리기로 함.
- **TA 콘텐츠의 정확한 형태** — "관리자 화면에서 참조풀처럼 핸들링"까지는 정해졌지만, 구체적으로 어떤 항목(제목/분류/본문 등)을 넣을지는 아직 안 정함.
- **탭 이동을 순서대로 강제할지** — 예전에 "자료준비/상담분석 모드 구분"을 없앤 이유가 "흐름은 이어지는데 모드별로 막혀서 오히려 불편했다"였음. 6탭도 순서는 이 흐름을 따르되, 실제 이동은 자유롭게(탭 아무거나 바로 클릭 가능) 두는 걸 추천. 확정 필요.
- **하단 탭 라벨/아이콘** — 6개로 늘어나면 글자 크기·아이콘이 화면에 맞는지 실제로 봐야 함.

## 6. UX/UI 관점 의견 (2026-09-06 추가)

실제 코드(`style.css`의 `nav.tabs`, `core.js`의 `header()`)를 확인하고 정리한 내용.

1. **탭 6개, 화면엔 들어가긴 함** — 하단 탭 바 최대 폭 520px에 원래 5개가 나눠 쓰던 구조(버튼당 글자 11px·아이콘 19px). 6개로 늘면 버튼당 폭이 20% 줄어듦. 라벨을 2~3글자로 짧게(예: "고객관리"→"관리") 줄이는 걸 추천 — 실제 1단계 구현에서 이렇게 반영함.
2. **"순서가 있는 흐름" vs "평평한 탭 구조"** — 하단 탭은 원래 자유 이동 방식이라 TA→고객관리로 이어지는 단계감이 탭 자체엔 안 드러남. 탭 이동은 자유롭게 두고, 각 화면 안에 "다음: ○○ →" 안내 버튼을 넣는 방식(분석 화면에 이미 있는 "참조풀에서 자료 선택/변경 →" 패턴)을 전체 6탭에 확장하는 걸 추천.
3. **홈 버튼 위치** — 화면마다 공통 헤더(`header()` 함수)가 이미 있고 거기에 홈 버튼이 있었음(원래는 왼쪽). 상단 우측으로 옮기는 건 헤더 함수 하나만 고치면 되는 간단한 변경(1단계에서 완료).
4. **TA 화면은 참조풀 읽기 화면 컴포넌트 재사용 추천** — 새로 배울 UI 없이 바로 익숙하게 쓸 수 있고 코드도 덜 늘어남. (2단계에서 적용 예정)
5. **고객관리 — Q&A보다 "자동 요약 먼저 보여주기"** — 매번 Q&A를 열어야 알 수 있는 구조보다, 화면 맨 위에 짧은 자동 요약 카드를 기본 노출하고 Q&A는 그 이상 궁금할 때만 쓰게 하면 사용성도 좋고 AI 호출 비용도 줄어듦.
6. **히스토리 타임라인 구분 표시** — 통화 기록 vs AP 상담 녹취를 아이콘/색으로 구분(참조풀 자료 종류 구분과 같은 패턴).
7. **탭이 좁아지면 오터치 위험** — 이동 중·운전 중 급하게 쓰는 앱 특성상, 아이콘 모양을 확실히 다르게 하고 색 구분에만 의존하지 않기.

## 7. 진행 순서 제안 (아직 실행 안 함, 제안만)

1. **1단계**: 하단 탭 6개로 재배치 + 홈을 상단 우측 아이콘으로 이동 (구조만, 화면 내용은 비워두거나 자리만 잡음)
2. **2단계**: TA 탭 — 관리자 화면에 자료 등록 칸 추가 + 담당자 화면에 읽기전용 표시 (참조풀과 같은 구조)
3. **3단계**: 고객관리 탭 — 음원 업로드 + "AI로 정리" → 히스토리 타임라인
4. **4단계**: 고객관리 안 Q&A 코너 (히스토리가 어느 정도 쌓인 뒤 마지막에 추가하는 게 안전)
