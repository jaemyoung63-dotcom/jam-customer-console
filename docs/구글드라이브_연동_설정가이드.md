# 구글 드라이브 연동 설정 가이드 (2026-09-06)

고객관리 화면의 "☁️ 구글드라이브에서 가져오기" 버튼을 실제로 작동시키려면, **구글 개발자 콘솔에서 jam님이 직접 설정해야 하는 부분**이 있어요(카카오 지도 설정 때와 똑같은 방식 — Claude가 대신 로그인해서 만들 수 없는 부분).

설정 다 끝나면 **API 키, 클라이언트 ID, 앱 ID(프로젝트 번호)** 이렇게 3가지 값을 저한테 알려주시면, 제가 코드에 연결할게요.

비용은 **무료**예요(이 용도로 쓰는 구글 API는 결제 정보 등록 없이 무료로 씀).

---

## 1단계. 구글 클라우드 프로젝트 만들기

1. https://console.cloud.google.com 접속 (구글 계정으로 로그인)
2. 상단 프로젝트 선택 메뉴 → "새 프로젝트" → 이름은 아무거나(예: jam-customer-console) → 만들기

## 2단계. API 2개 켜기

아래 두 링크에 각각 들어가서, 방금 만든 프로젝트가 선택된 상태에서 "사용" 버튼을 누르세요.

- Google Picker API 켜기: https://console.cloud.google.com/apis/enableflow?apiid=picker.googleapis.com
- Google Drive API 켜기: https://console.cloud.google.com/apis/library/drive.googleapis.com

(Picker API = 파일 선택창을 보여주는 기능, Drive API = 선택한 파일을 실제로 읽어오는 기능. 둘 다 필요해요.)

## 3단계. API 키 만들기

1. https://console.cloud.google.com/apis/credentials 접속
2. "사용자 인증 정보 만들기" → "API 키" 클릭 → 키가 생성되면 복사해서 어딘가에 메모
3. 방금 만든 키 옆의 "제한사항 수정" 또는 키 이름을 눌러 들어가기
4. **애플리케이션 제한사항** → "웹사이트"로 설정 → 아래 주소 두 개를 **꼭 둘 다** 추가:
   - `https://jam-customer-console.pages.dev/*`
   - `https://docs.google.com/*` ← 이걸 빼먹으면 "API developer key is invalid" 오류가 남(구글 파일선택창이 이 주소 안에서 열리기 때문)
5. **API 제한사항** → "키 제한" 선택 → "Google Picker API"와 "Google Drive API" 둘 다 체크
6. 저장

## 4단계. OAuth 클라이언트 ID 만들기 (로그인 동의 관련)

1. https://console.developers.google.com/auth/clients 접속
2. "클라이언트 만들기" → 애플리케이션 유형 "웹 애플리케이션" 선택
3. 이름은 아무거나(예: jam-customer-console web)
4. **승인된 자바스크립트 원본**에 추가: `https://jam-customer-console.pages.dev`
5. 만들기 → 생성된 **클라이언트 ID** 복사해서 메모 (비밀번호 같은 "클라이언트 보안 비밀"은 이 방식에선 안 씀 — 안 챙겨도 됨)

## 5단계. OAuth 동의 화면 설정 (처음 한 번만)

구글이 "이 앱이 내 드라이브에 접근해도 되는지" 사용자에게 물어보는 화면 설정이에요.

1. https://console.cloud.google.com/auth/overview 접속해서 안내에 따라:
   - User Type: **외부(External)** 선택 (구글 워크스페이스 계정이 아니면 이것만 선택 가능)
   - 앱 이름, 이메일 등 기본 정보만 입력
2. **테스트 사용자** 항목에 jam님과 담당자들 구글 계정 이메일을 추가해두면, "확인되지 않은 앱" 경고가 떠도 로그인해서 쓸 수 있어요 (최대 100명까지, 우리 팀 규모면 충분).
   - 구글 정식 심사(verification)까지는 필요 없어요 — 심사는 불특정 다수에게 공개할 때만 필요한 절차예요.

## 6단계. 앱 ID(프로젝트 번호) 찾기

1. https://console.cloud.google.com/iam-admin/settings 접속 (프로젝트가 맞게 선택되어 있는지 확인)
2. "프로젝트 번호" 라는 숫자를 복사

---

## 저한테 알려주실 것

위 과정을 마치면 아래 3가지를 저한테 알려주세요(대화창에 붙여넣으면 돼요):

1. **API 키** (3단계에서 만든 것)
2. **클라이언트 ID** (4단계에서 만든 것, `...apps.googleusercontent.com` 으로 끝나는 긴 문자열)
3. **앱 ID = 프로젝트 번호** (6단계에서 찾은 숫자)

이 3가지를 받으면 제가 `customermgmt.js`의 "☁️ 구글드라이브에서 가져오기" 버튼을 실제로 동작하게 연결할게요. (지금은 버튼을 눌러도 "준비중" 안내만 뜹니다.)

## 참고 — 이 값들이 노출돼도 괜찮은 이유

API 키·클라이언트 ID는 카카오 JS 키처럼 웹페이지 코드 안에 그대로 들어가서, 브라우저 개발자도구로 보면 누구나 볼 수 있어요. 이건 정상이고 원래 그렇게 쓰도록 설계된 값이에요(3단계에서 사이트 주소로 제한을 걸어두면 다른 사이트에서 도용 못 함). "클라이언트 보안 비밀"처럼 절대 노출되면 안 되는 값은 이 방식(웹 애플리케이션)에서는 아예 안 씀.
